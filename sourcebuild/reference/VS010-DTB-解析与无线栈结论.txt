容器格式（131156 B = 84 B 头 + 131072 B body）：
  "QCA-ATH11K-BOARD\0" + 对齐 + u64 长度 + u32 名字长度(37)
  + "bus=ahb,qmi-chip-id=0,qmi-board-id=NN" + 对齐
生成 board-cucc_vs010.ipq5018 (id=36) / .qcn6122 (id=96)：
  头逐字节沿用 kkstone 3000Q 样本，body 换成 VS010 BDF。
  另备 id=16 版本（对应 VS010 原厂 dtb 的 qcom,board_id=0x10）。

【r23 补：分区表实机口径】
  实机日志 cat /proc/mtd：mtd15 rootfs = 0x06e00000 (110 MiB)，
  mtd16..18 是 UBI 卷。vs010.dtb 的分区表 rootfs @0x00900000 size 0x06e00000
  与之逐字节一致 → 这台机器【已刷三方 U-Boot + 大分区 MIBIB】。
  核查报告第四章的「原厂 24 分区表」(rootfs_1/rootfs 各 0x2840000) 是原厂布局，
  不适用于这台。分区由 U-Boot 经 qcom,smem-part 填充，DTS 不写死 24 分区偏移。
  /proc/cmdline 还证明 bootargs-append 需含 "ubi.mtd=rootfs swiotlb=1"，r22 漏了，
  r23 已补。内核为 32 位 ARMv7（armv7l / vermagic ARMv7 p2v8），
  与 .config 的 CONFIG_TARGET_ipq50xx_arm=y 一致。

【r23 补：GPIO 实机值】
  wps 键 GPIO34 低有效（linux,code=529 KEY_WPS_BUTTON，debounce 60，pull-up）；
  没有独立 reset 键。LED：mesh GPIO33、pwr GPIO31，均低有效、pull-down。
  QCA8337 reset GPIO26、MDIO gpio36/37 —— 这几个 3000Q 与 VS010 相同。
  switch：cpu 0x40 / lan 0x1e / wan 0x00，8 对 ar8327-initvals，4 个 PHY 口；
  3000Q 是 0x48/0x34/0x02、4 对、6 个口。r23 默认保留 3000Q 档（有线已验证），
  实机值做成可选档 tools/apply-vs010-switch-oem.py。
  详见 reference/VS010-实机参数对照表.md。

【r22 策略】
  · 3000Q：真源码编译，原生 ath11k + NSS，插件自由增删，网口速率正常上报
  · 010：源码线默认可编，无线已补 VS010 板级 BDF；融合线保留作保底回退
  · ART 每台独立分区，刷机不覆盖；任何固件都不写 ART、不硬编码 MAC
  · 仍需实机确认：iw dev 是否出现双频接口、qmi-board-id 是否报 16、
