# VS010 无线修复 · 取证记录（r22）

## 一句话

**你是对的，无线能修。** 上一轮我把「原厂闭源 cnss2 栈」和「本编译线的开源
ath11k 栈」混在一起了：闭源栈确实搬不过来，但开源 ath11k 的 Q6/m3 固件由

## 交叉校验：这真是 VS010 的 BDF

QSDK 5.4 线从 `0:ART` 偏移 `0x1000`（2.4G）与 `0x26800`（5G）各取
`0x20000` = 131072 B。用你仓库里三份 ART 逐字节比对：

| ART | 2.4G@0x1000 | 5G@0x26800 |
|---|---|---|
| `VS010-smem_0-ART.bin` | 99.20% | 97.70% |
| `d83dcc685b5a-VS010-smem_0-ART.bin` | 99.27% | 97.69% |
| `RAX3000Q-mtd13-0ART` | 99.46% | 97.65% |

不一致的字节是每台唯一校准微调，板级模板一致 → 证实是 VS010 的板数据，
不是别的机型。原始数字见 `reference/ART-校验.json`。

## 容器格式（逆向自 kkstone 样本）

```
offset 0    "QCA-ATH11K-BOARD\0"          (17 B)
offset 17   "mmm\0\0\0\0"                  (对齐到 24)
offset 24   u64 LE = 131128                (剩余长度)
offset 32   u32 LE = 37                    (名字长度)
offset 36   "bus=ahb,qmi-chip-id=0,qmi-board-id=NN"  (37 B)
offset 73   "mmm"                          (填充)
offset 76   8 B + "02 00"
offset 84   131072 B 裸 board data         ← 与 whmzsu BDF 同构
总长        131156 B
```

裸 BDF 开头 `01 00 04 04 00 00 00 00 00 80 ...`，kkstone 样本 offset 84
起也是同一签名 → 只需换 body，格式零风险。

## board-id 对照（关键）

| | 2.4G `&wifi0` | 5G `&wifi1` |
|---|---|---|
| kkstone `ipq5000-rax3000q.dts` | `qcom,board_id = <0x24>` = 36 | `<0x60>` = 96 |
| `board-cmcc_rax3000q.*` 容器头 | `qmi-board-id=36` | `qmi-board-id=96` |
| VS010 原厂 `vs010.dtb` | `0x10` = 16 | `0x60` = 96 |

主产物沿用 **36 / 96**（Q6 固件与 DTS 都是这一套，已验证能工作），
只把板数据换成 VS010 的。另备 **16** 版本放在 `reference/variants/`，
若实机日志报 `qmi-board-id=16` 不匹配，换它重编即可。

## 装到哪

`ipq-wifi/Makefile` 的 `ipq-wifi-install-one`：
- `.ipq5018` → `/lib/firmware/ath11k/IPQ5018/hw1.0/board-2.bin`
- `.qcn6122` → `/lib/firmware/ath11k/qcn6122/hw1.0/board-2.bin`

`diy-part1.sh` 在 `feeds update` **之前**把两个 `board-cucc_vs010.*`
复制进主树 `package/firmware/ipq-wifi/` 并在 Makefile 注册 `cucc_vs010`；
`Device/cucc_vs010` 的 `DEVICE_PACKAGES` 选入
`ipq-wifi-cucc_vs010` + `ath11k-firmware-ipq5018` + `ath11k-firmware-qcn6122`。

🔴 坑已避开：备选的 `.boardid16.ipq5018` 放在 `reference/variants/`，
**不放** `package/ipq-wifi/` —— 否则会被 `wildcard board-cucc_vs010.*`
一并匹配，两个文件抢同一个 `board-2.bin` 互相覆盖。

## 🔴 r23 补：实机日志直接证实 BDF（比 ART 相似率更硬）

你仓库里的 `VS010文件.txt`（GBK 实机 SSH 日志）里有：

```
[   23.223383] cnss[2]: INFO: platform name: CUCC VS010
[   23.295847] cnss[2]: INFO: Downloading BDF: IPQ5018/bdwlan.b10, size: 131072
[   24.887795] cnss[41]: INFO: Downloading BDF: qcn6122/bdwlan.b60, size: 131072
[   23.659500] wlan: [1493:I:ANY] BDF version: 1 CAL version: 0 Status: 0
```

两个 BDF 都是 **131072 B**，正是 r22 从 `whmzsu/oem_extract/` 拉到的大小；
固件清单里也有 `/lib/firmware/IPQ5018/bdwlan.b10` 与
`IPQ5018/qcn6122/bdwlan.b60`。**就是同一份板数据**，无线修复方向被实机二次确认。

`iw dev` 还给出满血基线：`phy#2`（2.4G，ath0/wifi0）+ `phy#3`（5G，ath1/wifi1），
共 2 phy / 4 interface，已写进 `vs010-wifi-check`。

## 每台唯一校准

默认编译用通用 VS010 BDF（与 3000Q 用单个 `board-cmcc_rax3000q.*` 同理）。
想要本机专属校准：

```sh
dd if=/dev/mtd13 of=/tmp/my-art.bin bs=1M count=1   # 在已刷机器上导出 0:ART
python3 tools/make-vs010-bdf.py --art /tmp/my-art.bin
git add package/ipq-wifi/ && git commit -m "010 本机 ART 校准" && git push
# 重跑 Actions
```

`make-vs010-bdf.py` 也支持 `--id24 16` 生成备选 board-id 版本。

## 仍需实机确认（不假装已验证）

1. `iw dev` 是否出现 2.4G + 5G 两个接口；缺一个就 `vs010-wifi-check` 看日志里的 `qmi-board-id`。
2. 按键 GPIO：原厂 dtb 只有 `wps=GPIO34`；本骨架沿用 3000Q 的 `reset=23/wps=38`（你实机已验证能启动，故不动，避免回归）。恩山有互刷变砖案例，首次刷建议 TTL 在手边。
3. 网口排序：VS010 是 LAN3 直连 CPU 作 WAN（`switch_wan_bmp=0`），本骨架沿用 3000Q 位图；你有线能起，先不动。
4. `0:ART` 固定 MIBIB 24 分区，刷机不覆盖、固件不写 ART、全仓零硬编码 MAC。
5. 首次真 `make` 编译约 1–2 小时；本包只做静态与 mock 验证，没跑 GitHub Actions。
