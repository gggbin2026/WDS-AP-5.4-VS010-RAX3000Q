# VS010 实机日志取证（r23）· 你仓库里的 "VS010文件"

## 先回答你的问题：文件里有 GPIO 吗？

**严格说：`VS010文件.txt` / `A 好固件·阶段1.txt` 里没有 GPIO 编号。**

这两个文件是 **GBK 编码的实机 SSH / 串口日志**（直接读会报 "Unsupported file encoding"，
已解码转 UTF-8 留档在 `reference/upstream/user-logs/`）。里面只有
`gpio-button-hotplug.ko` / `leds-gpio.ko` 这类**驱动模块名**，没有任何
`gpio34` / `cat /sys/kernel/debug/gpio` / `swconfig` 输出。

**GPIO 编号在这两处**：
- `3000Q-VS010-固件/DTS/vs010.dtb` —— 运行态 FDT 二进制，311 节点，
  已解析出按键 / LED / pinctrl / 交换芯片全部数值（见 `reference/VS010-实机参数对照表.md`）
- `3000Q-VS010-固件/DTS/VS010与CMCC机型DTS资料核查报告.md` —— 文字版对比与变砖案例

所以「参考后再修复」该做，但取的是 **dtb + 日志**，不是 txt 里的 GPIO 字样。
r23 已按这两份实机资料把板级参数改回 VS010 自己的值。

## 日志里挖到的 8 条硬证据（比 r22 更值钱）

### 1. 🔴 实机直接证实 r22 拉到的 BDF 就是这台机器用的

```
[   23.223383] cnss[2]: INFO: platform name: CUCC VS010
[   23.295847] cnss[2]: INFO: Downloading BDF: IPQ5018/bdwlan.b10, size: 131072
[   24.887795] cnss[41]: INFO: Downloading BDF: qcn6122/bdwlan.b60, size: 131072
[   23.659500] wlan: [1493:I:ANY] BDF version: 1 CAL version: 0 Status: 0
```

r22 从 `whmzsu/vs010-openwrt/oem_extract/` 拉到的两个裸 BDF 正好都是
**131072 B**。原厂固件路径 `/lib/firmware/IPQ5018/bdwlan.b10` 与
`IPQ5018/qcn6122/bdwlan.b60` 也在固件清单里。这比 ART 相似率（99.2% / 97.7%）
更硬 —— **就是同一份板数据**。r22 的无线修复方向被实机日志二次确认。

### 2. 无线满血时的接口基线（`iw dev`）

```
phy#3  Interface ath1 / wifi1   ssid Nwrt_5G   ch149 5745 MHz 80MHz  txpower 27 dBm
phy#2  Interface ath0 / wifi0   ssid Nwrt_2.4G ch13  2472 MHz 40MHz  txpower 20 dBm
/sys/class/ieee80211/  → phy2  phy3
```

即 **2 个 phy / 4 个 interface**。已写进 `vs010-wifi-check` 作为比对基线。

### 3. 🔴 这台机器已刷三方 U-Boot + 大分区 MIBIB

```
mtd13: 00100000 "0:ART"
mtd14: 00080000 "0:TRAINING"
mtd15: 06e00000 "rootfs"          ← 110 MiB
mtd16: 003e0000 "kernel"           ← UBI 卷，erasesize 0x1f000
mtd17: 01531000 "rootfs"
mtd18: 04e97000 "rootfs_data"
```

`vs010.dtb` 的分区表：`rootfs @0x00900000 size 0x06e00000` —— **与日志逐字节一致**。
而核查报告第四章的「原厂 24 分区表」（`rootfs_1`/`rootfs` 各 `0x2840000`）是
**原厂**布局，不是这台机器。刷机教程里也明确写了 `mtd write mibib.bin /dev/mtd1`。

结论：**分区由 U-Boot 经 `qcom,smem-part` 填充，DTS 里不要写死 24 分区偏移**。
r22 文档里「固定 MIBIB 24 分区」的说法对这台机器不成立，r23 已更正。

### 4. `/proc/cmdline` 证明 r22 少传了两个参数

```
console=ttyMSM0,115200n8 ubi.mtd=rootfs root=mtd:ubi_rootfs rootfstype=squashfs \
rootwait ubi.mtd=rootfs root=/dev/ubiblock0_1 swiotlb=1 coherent_pool=2M
```
`vs010.dtb` 的 `bootargs-append` =
`" ubi.mtd=rootfs root=/dev/ubiblock0_1 swiotlb=1 coherent_pool=2M"`。

r22 DTS 里只有 `" root=/dev/ubiblock0_1 coherent_pool=2M"` —— **缺
`ubi.mtd=rootfs` 和 `swiotlb=1`**。r23 已补回。

### 5. 内核是 32 位 ARM，不是 aarch64

```
Linux Nwrt 5.4.213 #0 SMP PREEMPT ... armv7l GNU/Linux
vermagic=5.4.213 SMP preempt mod_unload ARMv7 p2v8
```
`.config.vs010` 是 `CONFIG_TARGET_ipq50xx_arm=y` / `CONFIG_TARGET_SUBTARGET="arm"`
—— **选对了**，别误改成 aarch64。

### 6. 原厂无线是闭源栈（再次印证 r22 的纠错）

`lsmod`：`qca_ol` / `umac` / `wifi_3_0` / `ipq_cnss2` / `qca_nss_dp`，
**没有 ath11k**。固件清单还有 `IPQ5018/q6_fw.mdt`、`m3_fw.mdt`、
`fw_ini_cfg.bin`、`regdb.bin`。这是原厂闭源 cnss2 链，与 kkstone 编译线的
开源 ath11k 是两条栈 —— r22 的更正成立。

### 7. 原厂固件带多个 board-id 变体

```
/lib/firmware/IPQ5018/bdwlan.b10 .b20 .b21 .b22 .b23 .b24 .bin
/lib/firmware/IPQ5018/qcn6122/bdwlan.b50 .b60 .b90 .bb0 .bin
```
如果 ath11k 编译时报别的 `qmi-board-id`，说明板子走的是另一个变体。
r23 的 `reference/variants/` 已备 id=16 版本；其余变体可从本机
`0:ART` 或原厂 `/lib/firmware` 导出后用 `tools/make-vs010-bdf.py` 生成。

### 8. 串口与 U-Boot 刷机口径（与现有配置一致）

`console=ttyMSM0,115200n8`（TTL 1.8V 注意）；刷机教程写
「拔电源按住 reset 插电 10 秒 → 浏览器 192.168.1.1」，LAN 口 TFTP
`serverip 192.168.1.254 / ipaddr 192.168.1.1`。r23 不动这些。
