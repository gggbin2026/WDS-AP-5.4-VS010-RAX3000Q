## 为什么 switch 那三行默认不改

你实机反馈「**网卡什么都能起来，只是无线**」→ 3000Q 档的 QCA8337 配置
在这块板上**已被验证能工作**。而 `qca,ar8327-initvals` 是 QSDK 闭源驱动的
私有寄存器初始化序列，`port_phyinfo` 决定 PHY 探测顺序 —— 改错的表现是
**开机 `qca8k`/ESS 探针超时、网口全灭**，比按键 GPIO 错的后果严重得多。

所以 r23 把实机值完整提取留档，做成**可选档**：

```bash
python3 tools/apply-vs010-switch-oem.py            # 切到实机 OEM 档
python3 tools/apply-vs010-switch-oem.py --restore # 逐字节回退到默认档
# 或在 Actions 里把 vs010_switch_oem 设为 true
```

切之前请 TTL 在手边；切完需实机用 `swconfig list` / 插线看灯核对
`02_network` 的 WAN/LAN 标签（脚本**不改** 02_network，因为 QSDK ESS
内部 port_id 与 uci 端口编号的映射无法从现有材料确定，不臆造）。

## 恩山变砖案例的边界（重要）

核查报告记的案例是「VS010 刷入 **CMCC RAX3000Q 的 U-Boot** 与大分区后，
复位键 GPIO 不一致，开机持续判定按键按下而循环重启，TTL 无法中断」。
那是 **U-Boot 层**的按键采样，不是内核 DTS 的 `gpio-keys`。

r23 改的是内核 DTS：改错**不会硬砖**，最多按钮/灯不灵或误触发 failsafe；
**U-Boot 千万别动**。你这台已经刷的是 VS010 对应的三方 U-Boot（分区表可证），
保持原样即可。
